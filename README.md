## What's actually on this site

- **Projects**, filterable by chain (SVM / EVM), each with a real case
  study, not a paragraph: the problem, the architecture decision, the
  bug that actually happened, and the current state, limitations
  included. A portfolio that only shows what works is just a
  highlight reel, and nobody's hiring a highlight reel to fix
  production at 2am.
- **Experience**, laid out like the resume it's summarizing, not
  dressed up as five separate case studies it doesn't have the
  content to support. Ambition is good; padding is a code smell.
- **Interactive diagrams** for the projects where the architecture is
  the actual interesting part: liquidation flow, LP-collateral via
  CPI, and a side-by-side of a real ERC-4626 exploit against two
  different fixes for it. Keyboard-navigable, because a diagram you
  can only explore with a mouse belongs in a PDF, and this isn't one.
- **Live-state badges** on projects with a public RPC endpoint, so
  "live demo" means live, not "screenshot I took the day it worked
  and never touched again."

## Stack, and why

| Layer | Choice | Reasoning, briefly |
|---|---|---|
| Framework | Next.js 16, App Router | Static generation, so a link pasted into Slack shows actual content, not four seconds of loading spinner and a recruiter who's already moved on |
| Animation | Framer Motion (+ GSAP, conditionally) | `whileInView` / `whileHover` cover almost everything; GSAP only gets invited if the diagrams' SVG paths need choreography Framer can't do alone |
| Components | Radix UI primitives, fully custom styling | Accessibility scaffolding without the visual DNA of every other site that installed the same component library and called it a day |
| Content | MDX per project, plain JSON for Experience | Projects need room to breathe; Experience is four fixed entries that don't need a content-management system to say "worked here, did this" |
| Blockchain reads | `@solana/web3.js` (SVM), `ethers.js`/`viem` (EVM) | Two chains that don't speak to each other, so two clients that don't pretend they do |
| Deploy | Vercel | The native home for Next.js, and the thing that made the live-RPC-badge idea stop being theoretical |

## Design

Dark, near-black, one accent color, no gradients, no glassmorphism,
no ambient particle field pretending to be a blockchain. The
node-and-line motif in the diagrams shows up again in the section
dividers, the nav's active-state indicator, and the Experience
timeline, on purpose: it's the same visual grammar doing the same job
twice, not a theme pack. If you came here for floating 3D cubes and a
neon gradient, you're thinking of every other web3 portfolio, and
that one's probably still open in another tab.

`prefers-reduced-motion` is respected everywhere. Motion here is
meant to clarify sequence and hierarchy, not perform enthusiasm.

## Project structure

```
src/
├── app/
│   ├── page.tsx                 # Home: hero, project grid, experience
│   ├── projects/[slug]/         # Case-study pages, MDX-driven
│   └── api/rpc/[program]/       # RPC proxy for live-state badges
├── components/
│   ├── projects/                # ProjectCard, ProjectGrid, ChainFilter
│   ├── experience/               # ExperienceTimeline (static JSON, no routing)
│   ├── diagrams/                 # Interactive SVG diagrams, one per architecture worth explaining
│   └── ui/                       # NodeDivider, Card, and friends
├── content/
│   ├── projects/*.mdx
│   └── experience.json
└── lib/                          # RPC clients, types, MDX utilities
```

## Running it locally

```bash
git clone https://github.com/raj-1106/<repo-name>
cd <repo-name>
npm install
npm run dev
```

```bash
npm run build      # catches SSR issues before Vercel does
npx tsc --noEmit   # type-check without emitting
npm run test       # unit tests for the non-trivial bits
```

## Known limitations, stated up front

- The RPC proxy's cache is in-memory and resets on cold start. That's
  an accepted tradeoff for current traffic, not an oversight — see
  the comment in `lib/rpc.ts` before you assume it's a real
  distributed rate limiter, because it isn't one.
- Enterprise Hyperledger Fabric client work is summarized at resume
  level only. The interesting parts are under NDA, which is, if
  nothing else, a strong signal the client took their own security
  seriously.
